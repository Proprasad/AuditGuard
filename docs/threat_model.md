# AuditGuard v3 — STRIDE Threat Model & Residual Risks

## 1. STRIDE Threat Matrix (Verified Against Source Code)

| STRIDE Category | Specific Threat | Enforced Countermeasure (Code Location) |
|---|---|---|
| **Spoofing** | Forged analyst approval, spoofed `reviewer_id`, or unauthenticated API / HTTP-MCP calls | PBKDF2-HMAC user auth + HS256 JWT with `jti` logout revocation (`src/api/auth.py`, `src/api/users.py`); `reviewer_id` derived strictly from `jwt.sub` (extra `reviewer_id` rejected `422`); maker-checker RBAC (`analyst` receives `403` on approve) plus four-eyes identity separation: the requester (recorded once in append-only `audit_logs` as `investigation_requested`) and the worksheet's last editor (`edited_by`, inside the hashed payload) can never prepare or approve it (`403 SELF_APPROVAL_FORBIDDEN`, enforced in `src/api/services/approval.py` and again inside the commit transaction in `src/db/case_repo.py`); the Chainlit UI signs every person in with their own account (`@cl.password_auth_callback`), never a shared service account; HMAC service token (`X-AuditGuard-MCP-Token`) on HTTP MCP transport (`src/mcp_servers/http_auth.py`). |

| **Repudiation** | Disputed audit trail for case closure, escalation, or prompt-injection events | Append-only `audit_logs` table storing `thread_id`, `event_type`, `actor`, `payload_hash`, and UTC timestamp (`src/db/database.py`); every LLM call logged with prompt/response/model/tokens/cost/latency and the prompt version to `runs/<run_id>/transcripts.jsonl` (`src/llm/client.py`). ## 2. Honest Residual Risks & Limitations

- **Novel Adversarial Paraphrases:** Regex and pattern-based prompt-injection detection (`detect_injection`) covers known English, Hinglish, Unicode homoglyph, and delimiter-breakout families (verified on `132` attacks with `0` false blocks on `320` benign memos), but semantic/indirect prompt injections using completely novel phrasing could still reach the LLM context. Defense-in-depth therefore relies on deterministic Verifier v2, RBAC tool allow-lists, and mandatory human approval rather than input filtering alone.
- **Synthetic Threat Coverage:** Red-team attacks and forged-registry probes are synthetic; live banking adversaries may combine multi-bank timing side channels, compromised merchant accounts with long histories, or external off-platform collusion beyond the visible transaction ledger.
- **Human Sign-Off Bottleneck:** Cryptographic human gating prevents autonomous regulatory filings, but security against rubber-stamping depends on trained compliance reviewers actually inspecting `missing_evidence`, competing hypotheses, and cited statutory passages before approving.
